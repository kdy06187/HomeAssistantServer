## stop / main 리뷰
- stop(): listen 전에 불려도 run() 종료까지 5ms 간격 반복 svr.stop() → 정지. 추가 테스트(start 직후 stop x20 각 2초 이내, idle keep-alive 연결 상태 stop 3초 이내, 미시작 stop, 이중 stop) 통과. 소멸자 이중 stop은 mIsRunning 선검사로 안전.
- 포트 바인드 실패: listen 반환 → mHasRunFinished=true → stop 즉시 종료.
- 문제점(낮음): start→stop→start 재시작 시 mHasRunFinished가 true로 남아 두 번째 stop이 svr.stop 없이 join → 영구 대기 가능, 라우트도 중복 등록. 재시작은 현재 사용처 없음. 지원 안 하면 start()에서 거부, 지원하면 플래그 리셋.
- 문제점(낮음): 동시에 두 스레드가 stop()을 부르면 두 번째는 즉시 반환(첫 stop 완료 전). 현재 사용 패턴에선 무관.
- main `for(;;) pause();` 뒤 코드는 도달 불가. SIGTERM/SIGINT 기본 동작은 즉시 종료(소멸자 미실행)라 이전과 같고, matter/tcp 정리·DB 정상 종료가 생략됨. 후속 권장: 시그널 핸들러로 플래그 후 정리 경로 실행.
