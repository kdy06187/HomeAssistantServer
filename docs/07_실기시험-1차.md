## 0. 시험 방식 — 운영 서버·운영 DB를 건드리지 않는다

### 0.1 왜 이렇게 하는가
- 서버는 `../config/…`, `../db/…`, `../third_party/…/chip-tool`, `../paa_certs/…`를 **실행 위치 기준 상대 경로**로 연다(`src/main.cpp`, `MatterController.hpp`). → 실행 위치를 `$FIELD/run/`으로 바꾸면 `$FIELD/config`, `$FIELD/db`를 쓰게 되어 **운영 파일과 완전히 분리**된다(코드 변경 없음).
- 포트 8000(REST)·8080(TCP)은 코드에 고정돼 있다. → **운영 서버와 동시에 켤 수 없다.** 시험 동안 운영 서버는 꺼 둔다.
- chip-tool의 Matter 저장소(KVS)는 서버 폴더가 아니라 `/tmp/chip_tool_config.ini`, `/tmp/chip_tool_config.alpha.ini`, `/tmp/chip_tool_kvs`에 있다(운영과 공용). → 시험 전에 **사본을 떠 두고**, 시험 뒤 필요하면 되돌린다.

### 0.2 준비 (읽기·복사만, 운영 파일은 읽기만)

| # | 할 일 | 명령 | 확인 |
|---|---|---|---|
| P-1 | 운영 서버가 켜져 있는지 확인(읽기) | `pgrep -a HomeAssistantCore; ss -ltn \| grep -E ':(8000\|8080) '` | 아무것도 안 나오면 꺼져 있음 → P-2 건너뜀 |

## 1. 서버 시작·DB 마이그레이션 (운영 DB **사본**, 결정: 첫 실행 백업 후 v1)

| 단계 | 내용 |
|---|---|
| 준비 | 0.2 P-1~P-9 끝, `$FIELD/db`에 `home_assistant.db`만 있음(`ls -la $FIELD/db`) |
| 실행 | 0.3으로 시험 서버 첫 실행 |
| 기대 결과 | 로그에 `✅ 데이터베이스 로드 완료!`, `$FIELD/db/home_assistant.db.bak-v0-<UTC시각>` 파일 1개(권한 `-rw-------`) |
| 실패 시 | `[DB] 백업 …` / `마이그레이션` 오류 로그를 그대로 기록하고 중단. 사본만 바뀐 것이므로 P-5로 다시 복사해 재시도 가능(1회까지) |

확인 SQL(서버를 끈 뒤 실행해도 되고, 켠 채 읽기만 해도 됨):
```bash
cd $FIELD/db
ls -la                                                         # .bak-v0-<UTC> 1개, 권한 600
sqlite3 -readonly home_assistant.db "PRAGMA user_version;"     # 1
sqlite3 -readonly home_assistant.db.bak-v0-* "PRAGMA user_version;"   # 0 (백업은 옛 버전 그대로)
sqlite3 -readonly home_assistant.db "PRAGMA integrity_check;"  # ok
sqlite3 -readonly home_assistant.db "SELECT name FROM pragma_table_info('devices') WHERE name IN ('ip','deleted_at');"   # ip, deleted_at
sqlite3 -readonly home_assistant.db "SELECT name FROM sqlite_master WHERE type='index' AND name='idx_history_device_time';"   # 1줄
sqlite3 -readonly home_assistant.db "SELECT device_id, ip FROM devices WHERE protocol_type=1;"   # ARD_<ip> 기기는 ip = ARD_ 뒤 문자열
# 행 수가 백업과 같은지(두 줄이 같아야 함)
for f in home_assistant.db.bak-v0-* home_assistant.db; do sqlite3 -readonly "$f" "SELECT (SELECT count(*) FROM devices),(SELECT count(*) FROM device_energy_stats),(SELECT count(*) FROM state_history_logs);"; done
# 운영 DB 원본 불변
sha256sum -c $FIELD/db-original.sha256                         # OK
```
- 두 번째 실행(서버 껐다 다시 켜기): **새 백업이 생기지 않아야** 한다(`ls $FIELD/db/*.bak-v0-*` 여전히 1개).
- 덤(C-12): `sqlite3 -readonly home_assistant.db "SELECT device_id FROM devices WHERE protocol_type=0;"` 의 시리얼이 영문·숫자·`_`·`-`, 64자 이하인지 눈으로 확인(값은 적지 않고 예/아니오만).
- C-13: SQLite 3.46.1(≥ 3.27, `VACUUM INTO` 가능) — 2026-11-20 확인됨.

| 결과 기록 | 값 |
|---|---|
| 백업 파일 생김·권한 600 | ☐ 예 ☐ 아니오 |
| user_version 1 / 백업 0 | ☐ / ☐ |
| ip·deleted_at 열, 인덱스 | ☐ / ☐ |
| 행 수 백업과 같음 | ☐ 예 ☐ 아니오 (devices·stats·history: ___ / ___ / ___) |
| 재실행 시 백업 추가 없음 | ☐ |
| 운영 DB 해시 OK | ☐ |
| C-12 시리얼 형식 | ☐ 모두 맞음 ☐ 벗어남 있음 |

## 2. Matter — 셸 없이 실행한 chip-tool (결정 18~22·25)

### 2.0 종료 코드·걸린 시간은 어디서 보나
| 보는 곳 | 무엇을 알 수 있나 |
|---|---|
| **서버 로그**(`$FIELD/logs/server-*.log`) | 서버는 chip-tool이 **0이 아닌 코드로 끝날 때만** `[MatterController] chip-tool 비정상 종료 (코드 N)`을 남긴다. 시간 초과면 `chip-tool 제한 시간 초과`, 실행 자체 실패면 `chip-tool 실행 실패`. → **명령이 성공했고 이 세 줄이 없으면 종료 코드 0** |
| **요청 걸린 시간** | `curl -w '%{time_total}'`(아래 명령에 포함) — chip-tool 실행 시간 + 약간 |
| **직접 실행(보조)** | 정확한 코드·시간이 필요하면 **시험 서버를 끈 뒤**(KVS 동시 사용 방지, 헬스체크가 60초마다 chip-tool을 돌림) `cd $FIELD/run && time ../third_party/connectedhomeip/out/host/chip-tool <같은 인자>; echo "exit=$?"`. 인자는 서버와 같다(아래 표) |

| 명령 | 서버가 넘기는 인자(셸 없음) | 제한 시간 |
|---|---|---|
| 켜기/끄기 | `onoff on|off <node> <ep>` | 5초 |
| 상태 | `onoff read on-off <node> 1` | 5초 |
| 전력 | `electricalpowermeasurement read active-power <node> 1`, `electricalenergymeasurement read cumulative-energy-imported <node> 1` | 각 5초 |

### 5.2 chip-tool stdin 방식(C-6, 2차 13번·ADR-008의 전제)
비밀값이 아닌 **가짜 표지 문자열**로만 시험한다. **시험 서버는 끈 상태**에서.

```bash
cd $FIELD/run; CT=../third_party/connectedhomeip/out/host/chip-tool
# ① 일반 명령이 stdin으로 실행되고, 입력이 끝나면 프로세스가 스스로 끝나는가
time (printf 'onoff read on-off <M-A node> 1\nquit\n' | $CT interactive start > $FIELD/logs/c6-1.txt 2>&1); echo "exit=$?"
# ② 공백·따옴표가 한 인자로 들어가는가 + 입력 줄이 출력·파일에 남는가 (가짜 값, 없는 노드)
time (printf 'pairing ble-wifi 999999 str:"FIELD MARKER_SSID" str:FIELD_MARKER_PW 20202021 3840 --timeout 15\nquit\n' | $CT interactive start > $FIELD/logs/c6-2.txt 2>&1); echo "exit=$?"
grep -c 'FIELD_MARKER_PW' $FIELD/logs/c6-2.txt                 # 출력에 남는지(0이면 안 남음)
grep -rl 'FIELD_MARKER_PW' /tmp/chip_tool* 2>/dev/null          # KVS·파일에 남는지(아무것도 없어야)
# ③ quit 없이 stdin만 닫으면 끝나는가
timeout 30 sh -c 'printf "onoff read on-off <M-A node> 1\n" | '"$CT"' interactive start > /dev/null 2>&1'; echo "exit=$?  (124면 30초 안에 안 끝남)"
```
- `20202021`은 Matter 공개 시험용 PIN, `999999`는 없는 노드라 실제 기기와 무관. ②는 BLE 탐색만 하다 실패하는 것이 정상.
- ① 출력에 성공 표지(`CHIP_NO_ERROR` 등)가 있는지도 기록(지금 판정 문구가 interactive 모드에서도 쓸 수 있는지).

| 결과 | 값 |
|---|---|
| ① stdin 명령 실행·성공 표지 | ☐ / ☐, exit=___, 시간 ___s |
| ② 공백 든 SSID가 한 인자로 | ☐ 예 ☐ 아니오 ☐ 모름 |
| ② 표지가 출력에 남음 | ☐ 남음(___회) ☐ 안 남음 |
| ② 표지가 /tmp 파일에 남음 | ☐ 남음 ☐ 안 남음 |
| ③ stdin 닫으면 종료 | ☐ 예 ☐ 아니오(quit 필요) |
