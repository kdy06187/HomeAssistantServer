# ADR-004: 테스트 프레임워크 — GoogleTest + GoogleMock (FetchContent 버전 고정)

- **날짜**: 2026-11-17
- **상태**: 채택(사용자 결정 Q-01, 2026-11-17)
- **관련 요구사항**: REQ-17, REQ-01, REQ-07, NFR-05, NFR-07, N-15

## 배경
테스트·경고 옵션이 없다(N-15). REQ-17은 한 번의 명령으로 단위·통합 테스트를 실행하고 가짜 드라이버를 제공하도록 요구한다. 외부 라이브러리는 승인 후 도입(G-6).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. GoogleTest + GoogleMock | 실무 표준, Mock 자동 생성, `gtest_discover_tests`로 `ctest` 연동 | 외부 의존 추가, 빌드 시간 증가 |
| B. Catch2 v3 | 문법 간단 | Mock 없음, 가짜를 전부 손으로 |
| C. 자체 assert + ctest | 의존 0 | 실패 메시지·픽스처를 직접 만들어야 함 |

도입 방식: FetchContent(버전 고정, 첫 빌드에 인터넷) / git 서브모듈 / 시스템 패키지(PC마다 버전 다름).

## 결정
A + FetchContent(특정 릴리스 태그 고정, 태그는 구현 단계에서 최신 안정판 확인 후 기록). 빌드 대상을 `hac_core`(CHIP·SimpleBLE 없음) / `hac_drivers` / `HomeAssistantCore` / `hac_tests`로 나누고, `-Wall -Wextra`는 우리 대상에만 켠다. `HAC_ENABLE_TSAN` 옵션으로 ThreadSanitizer 빌드를 만든다.

가짜 구분(Test Double):
| 가짜 | 방식 | 용도 |
|---|---|---|
| `MockMessageSender` | GoogleMock | PCDriver가 브로드캐스트를 1회 호출했는지 검증 |
| `FakeProtocolDriver` | 손으로 작성 | 지연(10초·15초)·실패·예외·OFFLINE 재현, 호출 기록 |
| `FakeClock` | 손으로 작성 | 45초 지연·90일 정리를 즉시 시험 |
| `FakeMacResolver`, `FakeChipToolRunner` | 손으로 작성 | ARP 결과, chip-tool 출력 고정 |

## 이유
- REQ-07의 가짜 주입을 표준 도구로 익힐 수 있다. 시간·지연이 필요한 가짜는 Mock보다 손으로 쓴 Fake가 읽기 쉽다.
- 라이브러리를 나누면 대부분의 테스트가 Matter SDK 없이 빨리 빌드된다.

## 감수하는 단점과 영향
- 첫 빌드에 인터넷이 필요하다(오프라인 PC는 캐시 또는 서브모듈로 전환 검토).
- 외부 라이브러리 라이선스: GoogleTest BSD-3-Clause(상업·개인 사용 가능, 고지 유지).
- 라이브러리 분리로 CMakeLists.txt 구조가 바뀐다(구현 단계에서 변경 목록 승인).

## 학습 포인트
- Test Double 종류(Mock/Fake/Stub), 단위 vs 통합 테스트, 의존성 고정(reproducible build), ThreadSanitizer.
