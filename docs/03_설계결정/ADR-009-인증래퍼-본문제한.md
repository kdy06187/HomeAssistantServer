# ADR-009: 인증 위치 — 라우트 래퍼(Decorator) + `Authenticator` 인터페이스 + 본문 크기 제한

- **날짜**: 2026-11-17
- **상태**: 채택(사용자 결정 Q-05 A, N-03 해결 a, 2026-11-17)
- **관련 요구사항**: REQ-15, REQ-11, NFR-03, N-03(신규), N-14

## 배경
- N-03(신규): POST에 잘못된 토큰을 보내면 앱이 401 대신 "unexpected end of stream"을 받는다. 추정 원인(통합 테스트로 확인 필요, C-10): 인증이 `set_pre_routing_handler`에서 본문을 읽기 전에 실행되고 401 후 연결을 닫아, 읽지 않은 본문 때문에 커널이 RST를 보낸다.
- REQ-15: 외부 접속을 고려한 인증 구조(토큰 교체, 시도 제한, 본문 제한, 실패 로그). 사용자 결정: 단일 Bearer + 인터페이스 분리 + 실패 로그 + 본문 제한.
- 현재 핸들러는 `json::exception`만 잡는다(N-14).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| a. 모든 라우트를 `addRoute` 한 함수로 등록하고, 그 안의 래퍼가 본문을 읽은 뒤 인증 → 핸들러 → 예외 500 → 직렬화 | httplib 수정 없음, 공통 예외 처리(N-14)·오류 매핑(ADR-003)을 같은 자리에서 | 래퍼를 거치지 않는 등록이 생기면 인증 누락 → 등록 함수를 하나로 강제 + 테스트 |
| b. 401에서도 연결을 유지해 httplib가 본문을 소비하게 함 | 기존 구조 유지 | httplib 내부 동작 의존, 가능 여부 미확인 |
| c. pre-routing에서 남은 본문을 직접 읽어 버림 | 변경 작음 | 그 단계에서 소켓 접근 수단 미확인 |

## 결정
a. 
- `HTTPServer::addRoute(method, pattern, handler)`만 `svr.Get/Post`를 부른다. 마지막에 `.*` 전체 매칭 라우트를 래퍼로 등록해 없는 경로도 인증 뒤 404 `NOT_FOUND`(v1.0의 "없는 경로도 토큰 틀리면 401" 성질 유지).
- `Authenticator`(Strategy 패턴) 인터페이스, 구현은 기존 `ApiAuth`를 쓰는 `BearerTokenAuthenticator` 하나.
- `svr.set_payload_max_length(16 * 1024)`: 본문을 먼저 읽게 되므로, 인증 안 된 요청이 서버에 큰 본문을 밀어 넣지 못하게 상한을 둔다.
- 실패 로그: 원격 주소(`clientAddressOf(req)`, ADR-011)·메서드·경로, 토큰은 일부도 기록하지 않음. 로그에 쓰는 외부 입력(경로·헤더·deviceId)은 제어문자를 `?`로 바꾸고 200자로 자른다(S-03). `X-Forwarded-For`는 외부 접속(프록시)을 붙일 때까지 쓰지 않는다(보류).
- 실패 횟수 경고: 래퍼가 1분 단위로 실패를 세어 10회를 넘으면 경고 로그 1회(차단은 안 함, S-02).
- 시도 횟수 제한·다중 토큰은 만들지 않는다(외부 노출 없음, 집 LAN 한정 — ADR-011). 필요해지면 래퍼 또는 새 `Authenticator` 구현에 추가.
- 연결 자원 상한(S-01, 2026-11-18 추가): 읽기·쓰기 타임아웃 5초(`set_read_timeout`·`set_write_timeout`), keep-alive 5초·최대 요청 수 제한(`set_keep_alive_timeout`·`set_keep_alive_max_count`), 작업 풀 8개(`new_task_queue`). 값은 통합 테스트(느린 연결이 있어도 정상 요청 처리)로 확정. 헤더 크기 한도는 확인 필요(C-9).
- 토큰(S-02, 2026-11-18 추가): 암호학적 난수 32바이트 이상(예 `openssl rand -hex 32`, 배포 문서). 시작 시 토큰이 32자 미만이거나 파일 권한이 0600보다 넓거나 소유자가 실행 계정이 아니면 경고 로그.

## 이유
- 본문을 읽은 뒤 응답하므로 RST 원인이 사라지고, httplib 코드를 건드리지 않는다.
- 인증·예외·오류 매핑이 한 함수에 모여 "모든 경로가 같은 규약"을 구조로 보장한다.

## 감수하는 단점과 영향
- 인증 전에 최대 16KiB를 읽는다(상한으로 감수). 느리게 보내는 연결 여러 개는 타임아웃·풀 크기로 줄일 뿐 완전히 막지 못한다(LAN 1인 환경이라 감수, S-01).
- 16KiB 초과 시 httplib가 자체적으로 413을 보내는데, 본문 모양과 연결 처리(같은 RST 문제가 생길 수 있음)는 확인 필요(C-9). 정상 앱은 이 크기를 넘지 않으므로 감수.
- 토큰 교체는 파일 교체 + 재시작(문서화).

## 학습 포인트
- Decorator(래퍼) 패턴, Strategy 패턴, 횡단 관심사(cross-cutting concern) 모으기, HTTP 연결 종료와 TCP RST.
