# ADR-007: 숨김 삭제, 이력 90일 보관, E7 기간·집계

- **날짜**: 2026-11-17
- **상태**: 채택(사용자 결정 Q-03a·b·c·d, 2026-11-17). 세부 방식은 제안
- **관련 요구사항**: REQ-12, REQ-13, NFR-06, APP-REQ, N-05, N-06, N-02(신규)

## 배경
- 삭제 시 `devices` 행만 지워져 통계·이력이 남는다(N-05). 이력은 인덱스·보관 정책이 없다(N-06).
- 앱은 일/주/월 사용량 보기를 원한다(APP-REQ). 지금은 최신 50건뿐.
- 사용자 결정: 원본 90일 보관 후 삭제 / limit 기본 50·최대 1000 / 서버 집계, +09:00 고정, 주는 월요일 시작 / **숨김 삭제, 90일 안 같은 ID로 재등록하면 복구하고 기록을 잇는다, 90일 뒤 기록까지 완전 삭제(같은 정리 작업)**.

## 선택지

숨김 삭제 표현:
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `devices.deleted_at` 칸(NULL=활성) | 한 칸 추가, 복구 = NULL로, 정리 = 날짜 비교 | 모든 조회에 "숨김 제외" 조건 필요(메모리 맵은 활성만 들고 있어 DB 조회 몇 곳만 해당) |
| B. `deleted_devices` 별도 테이블로 이동 | 활성 테이블이 깨끗 | 이동·복구 코드가 두 배, 통계·이력은 여전히 ID로 연결 |
| C. 행 삭제 + 통계·이력 즉시 삭제 | 가장 단순 | 사용자 결정(복구)과 다름 |

집계 위치:
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 서버 집계(`period=day/week/month`) | 앱 단순, 전송량 작음, 경계 계산 한 곳 | 서버에 날짜 계산 코드(C++17 표준엔 달력·시간대 없음 → 고정 오프셋) |
| B. 앱 집계(서버는 원본만) | 서버 단순 | 월 단위는 원본이 limit 초과 |

## 결정
- 숨김: A. 숨김 기기는 메모리 맵에 넣지 않으므로 E1 목록·헬스체크에서 자동 제외, E2·E5·E6·E7·E4는 404. 숨김 시 대기 중 지연 명령 취소, Matter는 chip-tool unpair + 매핑 파일에서 제거, TCP는 기존처럼 `RESET` 전송 후 연결 close. unpair 실패해도 숨김은 유지하고 응답 `unpaired:false`.
- 복구: 커미셔닝 결과 ID가 숨김 기기면 `deleted_at=NULL`, 이름·드라이버·ip를 새 요청 값으로 갱신, 통계·이력 유지. Matter는 재페어링으로 새 노드 ID를 받고 같은 시리얼로 복구. ~~활성 기기 ID가 다시 나오면 지금처럼 덮어쓰기~~ → **활성 기기 ID가 다시 나오면 덮어쓰지 않고 작업 실패 `ALREADY_REGISTERED`**(2026-11-18 정정, S-05: 덮어쓰면 PC 종료 지연 같은 부착 드라이버가 바뀔 수 있음). 복구되면 E8 `restored:true`와 `deviceId`로 앱이 사용자에게 알린다.
- 정리: `PeriodicTasks`가 시작 1시간 뒤 + 24시간마다 한 트랜잭션으로 ① 90일 지난 이력 삭제 ② `deleted_at`이 90일 지난 기기의 통계·이력·행 삭제. (시작 직후가 아닌 이유: 마이그레이션 직후 시계 이상이 겹치는 것을 피함, S-13)
- 정리 안전장치(S-13, 2026-11-18 추가): ① 시계 점검 — 마지막 이력 시각보다 90일 넘게 앞서 있으면 정리를 건너뛰고 경고 ② 삭제 비율 상한 — 지울 이력이 전체의 50%를 넘으면 건너뛰고 경고(시계가 미래로 튄 뒤 새 기록이 쌓여 ①을 통과해도 여기서 막힘). 정상 운영이면 새 기록이 쌓여 비율이 내려가므로 다음 주기에 다시 판단한다.
- 인덱스: `(device_id, timestamp)`.
- E7: `from`/`to`(현지 날짜, 포함), `period`(`day|week|month`), `limit`(기본 50, 최대 1000, 넘으면 1000으로 제한). 원본 모드는 "범위 안 최신 limit건을 오래된 순"(현재 동작 유지, N-02(신규) 설명 정정) + `truncated`. 집계 모드는 구간마다 `energyUsed_mWh`, `sampleCount`. 구간 사용량 = 이웃 표본 차이 중 양수의 합(뒤 표본이 속한 구간에 귀속), 음수 차이는 0(카운터 리셋 보정은 REQ-03에서 이미 `real_total`로 처리). 첫 구간 계산을 위해 범위 시작 직전 표본 1개를 함께 읽는다.
- 날짜 계산: 저장은 UTC 유지, 경계는 +09:00 고정. 날짜↔일수 변환은 공개된 civil-from-days 알고리즘(Howard Hinnant, 퍼블릭 도메인)을 순수 함수로 구현해 단위 테스트.

## 이유
- 사용자 결정을 가장 적은 스키마 변경(칸 2개 + 인덱스 1개)으로 구현한다.
- 이력 보관과 숨김 기기 완전 삭제가 같은 90일 기준이라 정리 작업 하나로 끝난다.
- 서버 집계는 경계 계산과 보정 규칙을 한 곳(테스트 가능한 순수 함수)에 둔다.

## 감수하는 단점과 영향
- ~~REQ-13 완료 기준("재등록 후 누적값 0에서 시작")과 반대~~ → R-1로 `01_요구사항.md`의 완료 기준을 숨김 삭제에 맞춤(2026-11-18).
- 시계가 오래 틀렸거나 서버를 90일 넘게 껐다 켜면 안전장치 때문에 정리가 미뤄질 수 있다(데이터 손실보다 낫다고 판단).
- 재페어링 뒤 Matter 플러그 자체 카운터가 0으로 돌아가는지 확인 필요(C-7). 줄어들면 기존 보정 규칙대로 현재값을 더한다.
- 90일보다 긴 월별 비교는 불가(요약 테이블 추가로 확장 가능, 지금은 만들지 않음).
- +09:00 고정이라 다른 시간대 사용자는 지원하지 않는다(1인·한국, 서머타임 없음).
- 표본 경계 귀속은 근사다(60초 간격이라 오차는 구간당 최대 1분 사용량).

## 학습 포인트
- Soft delete, 데이터 보관 정책(retention), 시계열 다운샘플링/집계, 타임존과 UTC 저장 원칙, 인덱스 설계.

## 12a 구현 반영 (2026-11-22)

결정 D1~D6은 변경 목록(`docs/11_변경목록-2차-12a.md`)의 추천안 A, 설계 차이 ①~⑤는 승인. 커밋 65d65ab·7047972·a9cebc5·cee662c·58a636c, dev·tsan 428/428. 위 결정에서 **구현이 구체화·달라진 점**:

| # | 내용 |
|---|---|
| 1 | `UtcTime`은 `gmtime_r`/`timegm`으로 구현. Hinnant civil-from-days는 `EnergyAggregation`(집계 구간 계산)에만 쓴다 |
| 2 | `DeviceManager`의 `clock_` 멤버를 12a-1에서 복원(11f에서 제거했던 것) |
| 3 | DB `markDeleted`·`queryHistory`·`purgeExpired`는 UTC를 DB 텍스트(`YYYY-MM-DD HH:MM:SS`)로 받는다. 안전장치 1 = "마지막 이력 < cutoff" |
| 4 | `deletedOrphans` = 고아 통계 행 + 고아 이력 행. 안전장치 2의 비율은 **90일 지난 이력만** 센다(고아·숨김 기기 삭제분은 비율 제외) |
| 5 | DB의 `getEnergyHistory`·`loadAllDevices`·`removeDevice`(하드 삭제) 제거. 시험은 `tests/support/HistoryTestHelper.hpp` |
| 6 | `removeDevice`에서 unpair 예외가 나도 숨김은 성공, `unpaired=false` |
| 7 | `runRetentionCleanup()`은 `Result<PurgeResult>`, 종료 중이면 `Cancelled`로 건너뜀 |
| 8 | `MatterController` unpair: 매핑 없음·타임아웃·`Error` 출력이면 `false` |
| 9 | 정리 루프 자체 시험은 없음. 순수 함수 `shouldRunCleanup`만(60번째 점검에서 첫 정리, 이후 1440번마다) |

남은 위험(수용): 시계가 90일 넘게 앞서면 정리를 건너뛰고 숨김 기기 완전 삭제도 미뤄진다(경고 로그). E7의 TCP 기기 400은 `FAKE_1`로만 시험했고 실제 `TCP_<MAC>` 확인은 12b.
