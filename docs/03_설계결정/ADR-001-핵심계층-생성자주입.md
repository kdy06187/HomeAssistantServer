# ADR-001: 핵심 계층 — 싱글톤 제거, 생성자 주입, 단방향 의존

- **날짜**: 2026-11-17
- **상태**: 제안
- **관련 요구사항**: REQ-07, REQ-01, REQ-17, NFR-05, N-08, B-03

## 배경
- `DeviceManager`·`DatabaseManager`·`DriverManager`가 싱글톤이라 테스트마다 전역 상태가 남고 가짜 드라이버를 끼우기 어렵다(REQ-07 "가짜 드라이버 주입").
- `ProtocolDriver`가 `DeviceManager&`를 들고 `addDevice`·`hasDevice`를 역호출한다(순환 의존). 이 역호출이 N-01 교착의 한쪽 경로다.
- 에너지 조회는 `ProtocolDriver`에 없어 `DeviceManager`가 구체 클래스 `MatterController`로 `dynamic_cast`한다.
- 기기 드라이버 예약이 기기 **이름** 키라 실패 시 남는다(N-08).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 현 구조 유지 + 락만 보강 | 변경 최소 | 순환 의존·싱글톤이 남아 가짜 주입·교착 제거가 어려움. REQ-07 미충족 |
| B. 싱글톤 제거 + 생성자 주입(Composition Root는 `main`) + 드라이버는 결과를 반환(역호출 제거), 아래→위 알림은 콜백 1개 | 표준 패턴, 테스트에서 가짜 교체 쉬움, 의존 방향이 한쪽 | 생성자 인자와 `main` 조립 코드가 늘어남 |
| C. 서비스 로케이터(전역 레지스트리에서 꺼내 씀) | 기존 호출부 변경 적음 | 의존이 숨어 보이지 않음(안티패턴으로 자주 지적), 테스트 격리 약함 |

## 결정
B. `main.cpp`가 모든 객체를 만들고 참조로 주입한다. `ProtocolDriver::commission`은 `CommissionOutcome`을 돌려주고 등록은 호출자(`CommissioningService` → `DeviceManager`)가 한다. TCP 접속 알림만 `TCPDriver::setConnectionListener` 콜백(Observer)으로 받는다. 에너지 조회는 `ProtocolDriver::readEnergy`(기본 "미지원")로 올린다. 기기 드라이버 예약 맵은 없애고 `driverTypes`를 커미셔닝 작업이 직접 들고 간다.

## 이유
- REQ-07 완료 기준(가짜 드라이버만으로 등록·제어·조회·삭제)을 가장 직접 만족한다.
- 역호출이 사라져 "락 쥔 채 남의 락" 경로가 구조적으로 줄어든다(ADR-002와 맞물림).
- 이름 예약이 사라져 N-08이 함께 해소된다.

## 감수하는 단점과 영향
- `main`이 길어진다(조립 순서가 한곳에 모이는 장점이기도 함).
- `readEnergy`를 기본 구현으로 둔 것은 인터페이스 분리 원칙(ISP)과 약간 어긋난다. 별도 `EnergyMeter` 인터페이스는 구현체가 하나뿐이라 지금은 과하다고 판단. 측정 기능이 있는 프로토콜이 늘면 분리한다.
- 클래스 이름(`DeviceManager`, `DriverManager`, `IDeviceDriver`, `DriverResult` 등)은 유지해 기존 코드 독자의 혼란을 줄인다.

## 학습 포인트
- 의존성 주입(Dependency Injection), Composition Root, 의존성 역전(DIP), Observer(콜백), 서비스 로케이터와의 차이.
