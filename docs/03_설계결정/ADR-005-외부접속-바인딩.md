# ADR-005: 외부 접속과 HTTP 바인딩 — Tailscale 전용, `127.0.0.1` + `tailscale serve`

- **날짜**: 2026-11-17
- **상태**: **보류 / 바인딩 결정은 대체됨(→ ADR-011)** — 2026-11-18 사용자 결정 "VPN(Tailscale)은 일단 빼고 집 LAN 먼저". 외부 접속(REQ-14·Q-02)·I-06을 다시 다룰 때 이 문서를 다시 연다. 아래 내용은 그때를 위한 기록이며 지금 설계에는 적용하지 않는다.
- (이전 상태: 제안. 상위 결정 Q-02a Tailscale·외부 포트 미개방, Q-02b 프록시 미사용은 사용자 채택 2026-11-17)
- **관련 요구사항**: REQ-14, REQ-15, NFR-03, I-06, A-05

## 배경
- 지금은 `0.0.0.0:8000` 평문 HTTP라 집 LAN의 누구나 토큰을 엿볼 수 있다(I-06).
- 사용자 결정: Tailscale(개인용 무료) VPN, 외부 포트 안 엶, Caddy 없음, HTTPS가 필요하면 `tailscale serve`.
- 남은 질문: 집 Wi-Fi에서 직접(평문) 접속을 허용할지, 서버를 어느 주소에 묶을지.
- 제약: DIY 기기는 TCP 8080으로 LAN에서 접속하고 펌웨어는 바꿀 수 없다 → 8080은 LAN에 남아야 한다.

## 선택지
| 선택지 | 집 Wi-Fi 직접 | 장점 | 단점 |
|---|---|---|---|
| A. `0.0.0.0:8000` 유지(LAN 평문 + tailnet 평문) | 허용 | 변경 없음, Tailscale이 꺼져도 집에서 사용 | LAN 평문 토큰 노출(I-06) 그대로. REQ-14 "평문 8000 외부에서 닫힘" 미충족(LAN 기준) |
| B. tailnet IP(`100.x.y.z:8000`)에만 바인딩 | 불가 | LAN 노출 없음, WireGuard로 암호화 | HTTPS 아님(REQ-14 문구 미충족), tailscaled보다 서버가 먼저 뜨면 바인딩 실패 → 시작 순서·재시도 필요, IP 하드코딩 |
| C. **`127.0.0.1:8000` + `tailscale serve`(443 HTTPS → 127.0.0.1:8000)** | 불가(집에서도 Tailscale 경유, 같은 LAN이면 직접 경로) | 공인 인증서 HTTPS(앱 설정 간단), 서버 포트가 어떤 네트워크에도 안 보임, 집·밖 주소 하나, Tailscale 공식 권장(백엔드는 localhost) | 휴대폰 Tailscale 상시 필요, Tailscale 장애·키 만료 시 접속 불가, 로그의 클라이언트 IP가 127.0.0.1 |
| D. LAN IP + tailnet IP 둘 다(서버 2개 listen) | 허용 | 두 경로 모두 | 코드 복잡(httplib 인스턴스 2개), LAN 평문 문제 그대로 |

## 결정
C. HTTP 바인딩 기본값 `127.0.0.1`, 환경 변수 `HAC_HTTP_BIND`로만 바꿀 수 있게 한다(전환기·비상용). TCP 8080은 `0.0.0.0` 유지(LAN 기기용, 공유기 포트포워딩 없음).

## 이유
- REQ-14 완료 기준("외부 경로로 HTTPS 성공, 평문 8000 닫힘")을 문자 그대로 만족한다. `tailscale serve`가 TLS 종단 리버스 프록시 역할을 한다.
- I-06을 집 안에서도 없앤다. 1인 사용이라 "항상 Tailscale"의 불편이 작다.
- 서버 코드 변경은 바인딩 주소 설정 하나뿐이다.

## 감수하는 단점과 영향
- Tailscale이 안 되면 앱도 안 된다. 비상시 `HAC_HTTP_BIND=0.0.0.0`으로 재시작(평문, 위험 인지 후)하는 절차를 배포 문서에 둔다.
- 서버 노드의 키 만료(기본 만료 있음)를 끄거나 갱신 일정을 관리해야 한다(설정은 사용자, 확인 필요).
- `*.ts.net` 인증서는 공개 인증서 투명성 로그에 기기 이름이 남는다 → 기기 이름에 개인정보를 넣지 않는다.
- 인증 실패 로그의 IP가 127.0.0.1이 된다. serve가 `X-Forwarded-For`를 넣는지 확인 필요, 있으면 함께 기록.
- 앱은 기본 주소를 `https://<서버 기기명>.<tailnet>.ts.net`(포트 없음)으로 바꿔야 한다(계약 v2.0 §1, §7).
- REQ-15의 시도 횟수 제한은 구현하지 않는다(외부 노출 없음). 공개 노출(Funnel·포트포워딩)로 바꾸면 이 ADR을 대체하고 제한을 추가한다.

## 학습 포인트
- 바인딩 주소의 의미(0.0.0.0 / 특정 IP / 루프백), 리버스 프록시와 TLS 종단, 제로 트러스트 VPN(WireGuard), 공격 표면 줄이기.
