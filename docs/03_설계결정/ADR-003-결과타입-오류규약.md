# ADR-003: 명령 결과 타입과 오류 응답 규약

- **날짜**: 2026-11-17
- **상태**: 제안
- **관련 요구사항**: REQ-07, REQ-11, REQ-04, I-01, I-02, I-03, I-05, N-01(신규), B-03, N-14, N-17

## 배경
- N-01(신규)/B-03: `executeCommand`가 기기만 있으면 true → 하드웨어 실패·지연도 "명령 성공!".
- I-05/N-17: HTTP 상태를 응답 본문에 `"error"` 문자열이 있는지로 정한다. 오류 본문이 2종, 키 표기가 섞였다.
- N-14: `json::exception`만 잡는다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `bool` 유지 + 로그 | 변경 없음 | 성공/실패/지연 구분 불가(REQ-07 미충족) |
| B. 예외 계층(`DeviceNotFoundException` 등)을 HTTP 계층에서 잡아 변환 | C++ 관용, 호출부가 짧음 | 예상 가능한 실패(기기 꺼짐)까지 예외 → 흐름이 보이지 않음, 헬스체크 스레드에서 놓치면 B-01처럼 종료 위험 |
| C. 결과 값(Result 패턴): `CommandResult{Succeeded/Accepted/Failed}`, `Result<T>`/`Status` + `ErrorCode` 열거형, HTTP 계층의 **단일 매핑 표** | 실패가 타입에 드러남, 표 기반 테스트 쉬움, 예외는 "예상 못 한 것"만 | 반환 타입이 늘어남, C++17에 `std::expected`가 없어 작은 구조체를 직접 둠 |

## 결정
C. 예상 가능한 실패는 `ErrorCode`를 담은 값으로 돌려주고, 예상 못 한 예외는 라우트 래퍼(ADR-009)가 잡아 500 `INTERNAL_ERROR`로 바꾼다. 오류 본문은 하나:

```json
{"error": {"code": "DEVICE_NOT_FOUND", "message": "등록되지 않은 기기입니다."}}
```

주요 매핑: 400 `INVALID_REQUEST`/`UNSUPPORTED_OPERATION`, 401, 404 `DEVICE_NOT_FOUND`/`JOB_NOT_FOUND`/`NOT_FOUND`, 409 `COMMAND_BLOCKED`/`COMMISSION_BUSY`, 413, 500, 502 `DEVICE_UNREACHABLE`. E2는 성공 200, 지연 수락 202. 전체 표는 `docs/02_설계.md` 3.5. 키는 lowerCamelCase, 단위 접미사 `_mW`·`_mWh`만 예외로 유지.

**고정 문구 규칙(S-11, 2026-11-18 추가)**: 응답의 `message`는 `ErrorMapping`이 `ErrorCode`별 고정 한국어 문구로만 만든다. `Error.message`(SQLite 오류, 경로, chip-tool 출력, `e.what()` 등 상세)는 로그에만 쓴다. 커미셔닝 결과용 코드에 `ALREADY_REGISTERED`(활성 기기를 다시 등록, S-05)를 추가한다.

## 이유
- REQ-07의 "성공/실패/지연 명확한 반환"과 REQ-11의 "처리 결과로 상태코드 결정"을 한 타입 체계로 해결한다.
- 기기 응답 없음을 502로 둔 이유: 서버는 정상이고 "뒤쪽 장치(게이트웨이 너머)"가 실패했다는 HTTP 표준 의미(Bad Gateway)와 맞다. 503은 서버 자체 과부하·정지 의미라 피했다.
- 지연 수락을 202로 둔 이유: "받았고 나중에 처리한다"는 표준 의미(Accepted).

## 감수하는 단점과 영향
- REST v2.0 MAJOR 변경(앱 수정 필요). 1차 릴리스에서는 v1.0 응답 모양을 그대로 내고(실패 시 "명령 실패!"), v2.0 매핑은 2차에 켠다.
- 400 안에 `INVALID_REQUEST`와 `UNSUPPORTED_OPERATION`이 같이 있다 → 앱은 HTTP 코드가 아니라 `code`로 분기해야 한다.
- 오류 코드 추가는 MINOR(앱은 모르는 코드를 일반 오류로 처리).

## 학습 포인트
- Result(Either) 패턴과 예외의 역할 분리, HTTP 의미론(202/404/409/502), 표 기반 테스트(Table-driven test).
