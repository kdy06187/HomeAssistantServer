## 0. 준비

### 0.1 시험 빌드 확인 (개발 폴더 `build-dev` — 운영 `build/`는 건드리지 않음)


2. 시험 실행 파일이 그 코드로 빌드됐는지 확인하고, 필요하면 빌드(개발 폴더라 운영 영향 없음):

### 0.5 🔒 운영 서버 중지
운영 1차(`87c805e`)에는 SIGINT/SIGTERM 정리 절차가 없다 — `Ctrl+C`로 바로 끝난다(정리 없이 종료, DB는 SQLite라 안전).
```bash

```
그 창에서 `Ctrl+C` → `Ctrl+b` `d`로 빠져나온 뒤:
```bash
pgrep -af '^./HomeAssistantCore'; pgrep -a chip-tool; ss -ltnp | grep -E ':(8000|8080) '
```
기대: 세 명령 모두 아무것도 안 나옴(8000·8080이 빔). 나오면 멈춘다.

### 0.6 🔒 운영 Matter 저장소 복사(결정 (가) — 운영 파일은 읽기만)
운영이 멈춘 **뒤에** 복사해야 파일이 쓰는 중이 아니다. 먼저 운영 파일 해시를 남기고(끝낼 때 비교), 복사한다:
```bash
( cd $REPO/config && find chip-tool registered_devices.txt -type f -print0 | sort -z | xargs -0 sha256sum ) > $T/prod-config.sha256 && chmod 600 $T/prod-config.sha256
```
```bash
cp -a $REPO/config/chip-tool $T/config/ && cp -p $REPO/config/registered_devices.txt $T/config/ && chmod 700 $T/config/chip-tool && chmod 600 $T/config/registered_devices.txt && stat -c '%a %n' $T/config/chip-tool $T/config/registered_devices.txt
```
기대: `700 …/chip-tool`, `600 …/registered_devices.txt`.

시험에 쓸 플러그 시리얼 확인(시리얼·노드 번호는 비밀값 아님):
```bash
cut -d, -f1 $T/config/registered_devices.txt
```
→ `PLUG_SERIAL=<시험할 플러그 시리얼>`. 플러그에는 **PC가 아니라 전등**을 꽂아 둔다.

### 0.7 시험 DB 만들기 + 플러그 행 넣기
1. 시험 서버를 한 번 켜서 새 DB(v1)를 만든다(HTTP는 이 PC에서만 받게 `127.0.0.1`):
   ```bash
   cd $T/build && HAC_HTTP_BIND=127.0.0.1 HAC_PC_AGENT_MAC=$AGENT_MAC ./HomeAssistantCore
   ```
   기대: `[Main] PC 에이전트 ID: TCP_<12자>`, `✅ 데이터베이스 로드 완료!`, (기기 로드 뒤) `[TCPDriver] 0.0.0.0:8080 에서 클라이언트 연결 대기 중...`. 확인 뒤 `Ctrl+C` → `[Main] 종료 완료`(`TCP 서버 종료`는 1번).
2. 서버가 꺼진 상태에서 플러그 행을 넣는다. `protocol_type` 0 = MATTER, `driverTypes` `'1'` = PC_DRIVER, `is_active` 1 = ON으로 로드:
   ```bash
   sqlite3 $T/db/home_assistant.db "INSERT INTO devices (device_id, display_name, protocol_type, is_active, driverTypes) VALUES ('$PLUG_SERIAL', '시험 플러그', 0, 1, '1');" && sqlite3 -readonly $T/db/home_assistant.db "SELECT device_id, protocol_type, is_active, driverTypes FROM devices;"
   ```
   기대: 한 줄 `<시리얼>|0|1|1`.
   - 이 방법을 고른 이유: E3로 Matter 등록을 하면 **다시 페어링**해 운영 fabric과 노드 번호가 달라진다. 시험 DB에 행만 넣으면 복사한 저장소의 기존 페어링을 그대로 쓴다(서버 코드의 `insertDevice`와 같은 열·값).

## 4. 위험·질문
- 메인 PC에서 원본 `pc_client.pyw`가 돌고 있으면 6번 메시지가 원본에도 갈 수 있고 **PC가 꺼진다**(같은 MAC) → 5·6번 전에 0.4의 프로세스 확인을 반드시 한다. 시험 사본은 SHUTDOWN을 받아도 끄지 않는다(결정 (나)).
- 복사한 저장소로 시험 서버가 Matter 명령을 보내면 그 세션·카운터는 시험 사본에만 남는다. 운영은 다음 명령 때 새 세션을 맺으므로 2.5처럼 첫 명령이 느릴 수 있다. 그래도 운영 제어가 계속 실패하면 운영 서버를 한 번 재시작하고 다시 시도, 그래도 안 되면 총괄에 알린다(운영 저장소 자체는 2.2에서 그대로임을 확인).
- 등록 중(최대 약 36초, 대기 20초 확정 뒤 약 26초)에는 서버를 끄지 않는다(종료가 그만큼 늦어짐 — 13번 취소 플래그로 해소 예정).
- 3번에서 스위치를 초기화하면 운영(1차) 쪽 스위치 동작은 스위치 IP가 바뀌었는지에 달려 있다(2.5).
