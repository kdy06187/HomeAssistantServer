# 13 실기 시험 절차서(초안) — 2차 12b TCP 고정 ID·PC 에이전트·T5

| 항목 | 값 |
|---|---|
| 상태 | **초안(실행 전)**. 사용자가 직접 실행한다. 🔒 줄은 운영·실물에 영향이 있어 실행 전 승인 |
| 기준 | 12b 구현 main(이 문서를 커밋한 커밋), 변경 목록 `12_변경목록-2차-12b.md` 6절, `09_설계보완-2차.md` 3절 K-5·K-6·K-8·K-9·K-10·K-11 |
| 전제 | 운영 서버(tmux `hac`, 1차 `87c805e`)와 포트 8000·8080이 같아 **동시 실행 불가** → 시험 동안 운영 중지. 시험은 **새 폴더·새 DB**(운영 DB·`config` 미사용). 시험 빌드는 v2.0 응답이라 **앱 대신 `curl`로만** 확인 |
| 비밀값 | API 토큰은 화면·문서에 쓰지 않는다. 시험 폴더의 `config/api_token`을 새로 만들고, `curl`에는 `TOKEN` 환경 변수로만 넘긴다 |

## 0. 준비

1. 시험 폴더 만들기(운영 폴더와 같은 깊이 구조: 실행 파일은 `build/`, 상대 경로 `../db`·`../config`·`../paa_certs`).
   ```bash
   mkdir -p ~/hac-12b-test/{build,db,config} && cp build-dev/HomeAssistantCore ~/hac-12b-test/build/ && ln -s "$PWD/paa_certs" ~/hac-12b-test/paa_certs
   ```
2. 시험 전용 토큰(새 값, 화면에 출력하지 않음):
   ```bash
   (umask 077; openssl rand -hex 32 > ~/hac-12b-test/config/api_token)
   ```
   `curl`용: `export TOKEN="$(cat ~/hac-12b-test/config/api_token)"`(이 셸에서만).
3. 에이전트 PC의 MAC 확인(Windows: `ipconfig /all`의 Wi-Fi 또는 이더넷 "물리적 주소"). Wi-Fi라면 그 SSID에서 **임의 하드웨어 주소가 꺼져 있는지** 먼저 확인(켜져 있으면 접속마다 MAC이 바뀌어 R-7 경고 + 45초 뒤 차단).
4. 🔒 **운영 서버 중지**: tmux `hac` 창에서 `Ctrl+C`(SIGINT, 종료 순서대로 정리). 끝나면 6절의 재시작을 반드시 한다.
5. 시험 서버 시작(새 tmux 창 `hac-test` 권장):
   ```bash
   cd ~/hac-12b-test/build && HAC_PC_AGENT_MAC=<에이전트 MAC> ./HomeAssistantCore
   ```
   기대 로그: `[Main] PC 에이전트 ID: TCP_<12자>`, `[TCPDriver] 0.0.0.0:8080 에서 클라이언트 연결 대기 중...`.

## 1. 확인 항목

| 순서 | 확인(09 3절) | 방법 | 기대 | 🔒 |
|---|---|---|---|---|
| 1 | K-9 ARP stale(가능하면) | 스위치 IP가 바뀐 직후 접속 로그의 `기기 ID [TCP_…]`가 이전과 같은지. 읽기만: `cat /proc/net/arp` | 같은 `TCP_…`. 다르면 기록(ADR-006 수용 위험) | — |
| 2 | 스위치 ID·K-8 | 스위치가 붙으면 로그 `기기 ID [TCP_<MAC>]`. 상태 조회 몇 번(아래 3의 E5) | 첫 조회 뒤 `버린 잔여(1회 진단): 0d 0a` 1번, 이후 `남아 있던 입력 … 버림` 없음. `0d 0a`가 아니면 값 기록 → 다시 판단 | — |
| 3 | K-11·K10 | 시험 DB에 스위치 등록(4의 재등록으로). 그다음 `curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8000/api/devices/<ID>/state` / `…/energy` / `…/energy/history` / `…/api/devices` | E5 200, E6·E7 400 `UNSUPPORTED_OPERATION`, E1에 `"ip":"<스위치 IP>"` | — |
| 4 | K-5 등록 대기 | 스위치를 BLE 등록 모드로 되돌려 E3 TCP 등록 5회(1회는 공유기 재시작 직후). `curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"protocolType":"TCP_DIY","deviceName":"test","payload":"<서버 IP>","ssid":"<SSID>","password":"<비밀번호>"}' http://127.0.0.1:8000/api/commission` (비밀번호는 셸 기록에 남으니 `read -s PW`로 받아 넣는 것을 권장) | 로그 `와이파이 설정 전송 완료` → `기기 ID [TCP_…]` 간격(초)을 5회 기록, `커미셔닝 완료 : … (N초)`. 최댓값×3(20~30초)으로 `kCommissionConnectWaitSeconds` 확정(바꾸면 한 줄 커밋, 승인) | 🔒 스위치 초기화(운영 1차 DB의 `ARD_<IP>` 등록은 IP가 같으면 계속 동작, 바뀌면 운영에서 재등록 필요). 🔒 공유기 재시작 |
| 5 | K-6 에이전트 재접속 | 에이전트 PC에서 에이전트 실행 → 로그 `기기 ID [TCP_…] … (PC 에이전트)`가 그 PC MAC과 같은지 → 시험 서버를 `Ctrl+C`로 끄고 다시 켬 | 에이전트가 다시 붙는지, 간격(초) 기록. `PC 에이전트 연결 교체` 경고는 에이전트가 끊지 않고 새로 붙을 때만 | — |
| 6 | K-10 T5 ① | **플러그에는 PC가 아니라 전등을 꽂는다.** PC_DRIVER를 붙여 등록한 Matter 플러그(시험 DB) ON → `curl … -d '{"deviceId":"<플러그>","command":"OFF"}' …/api/control` | 응답 202(45초). 에이전트 로그에 SYSTEM 수신, 스위치 로그에 SYSTEM 없음, 서버 로그 `PC 에이전트(TCP_…)가 종료 메시지를 받음`, 스위치 응답 지연 없음. 45초 뒤 전등 꺼짐 | 🔒 **에이전트가 실제로 PC를 끈다** — 에이전트에는 "수신만 표시" 모드가 없으므로 **꺼져도 되는 PC**에서 실행(작업 저장) |
| 7 | K-10 T5 ② | 에이전트를 끈 상태에서 6과 같이 OFF | 경고 `PC 에이전트(TCP_…) 연결 없음 — 종료 메시지 못 보냄, 45초 뒤 전원 차단`, 스위치에 SYSTEM 없음, 45초 뒤 전등 꺼짐 | — |
| 8 | 미설정·형식 오류 | 시험 서버를 끄고 `./HomeAssistantCore`(변수 없이) → 경고 1회 확인 후 끔 / `HAC_PC_AGENT_MAC=zz ./HomeAssistantCore; echo $?` | 경고 `HAC_PC_AGENT_MAC 미설정 — PC 종료 메시지를 모든 연결에 보냄` / 형식 오류 로그 + `1`(서버 안 뜸) | — |
| 메모 | 미식별 30초 | MAC을 못 찾는 접속이 있으면 로그 `미식별 연결(MAC 조회 실패): <IP>` → 30초 뒤 `미식별 연결 닫음` | 실기에서는 거의 없어야 함(있으면 IP·시각 기록) | — |

## 2. 끝내기

1. 시험 서버 `Ctrl+C`, 로그에서 `[Main] 종료 완료` 확인.
2. 🔒 **운영 서버 재시작**: tmux `hac` 창에서 운영 폴더의 `build/`로 가서 기존 방식 그대로 `./HomeAssistantCore`. 앱에서 목록이 보이는지 확인.
3. 4에서 스위치를 초기화했다면: 운영(1차) DB의 `ARD_<IP>` 기기는 스위치 IP가 같으면 계속 동작. 다르면 운영에서 삭제 후 재등록.
4. 시험 폴더(`~/hac-12b-test`)는 결과 기록 뒤 지워도 된다(토큰 포함).

## 4. 위험·질문
- 6번은 에이전트 PC가 실제로 꺼진다(에이전트 코드에 수신만 표시하는 모드가 없음). 다른 방법(예: 에이전트에 시험 모드 추가)이 필요하면 [Server]가 고치지 않고 총괄 요청으로 남긴다.
- 등록 중(최대 약 36초)에는 서버를 끄지 않는다(종료가 그만큼 늦어짐 — 13번 취소 플래그로 해소 예정).
