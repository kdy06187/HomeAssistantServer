## 2. 바꿀 것

### 14a-1 시험 HTTP 서버를 포트 0으로 띄우기 (D1=A 기준)
| 파일 | 변경 |
|---|---|
| `include/HTTPServer.hpp`·`src/HTTPServer.cpp` | ① 포트 검사를 `0~65535`로 바꾼다(0 = OS가 고름. `TcpServer`와 같은 규약). ② `start()`에서 0이면 httplib `bind_to_any_port(주소)`가 돌려준 포트를, 아니면 `bind_to_port` 결과를 저장한다. ③ `int boundPort() const`를 추가한다(실행 중이 아니면 0). ④ 시작 로그의 "포트"는 실제 포트로 찍는다. main은 8000을 넘기므로 동작이 같다 |
| `tests/support/RawHttpClient.hpp` | `findFreePort()`는 **남긴다**. 시작하지 않는 서버(`neverStarted`)와 "이미 쓰는 포트" 시험에 쓴다. 주석을 "시작하지 않을 때만"으로 고친다 |
| 서버를 시작하는 시험 8파일(`HttpServerTest`·`HttpServerAuthTest`·`HttpServerLimitsTest`·`HttpServerSlowTest`·`HttpServerLifecycleTest`·`EnergyPathTest`·`LockRulesTest`, 픽스처와 개별 시험) | `port = findFreePort(); HTTPServer s(..., port)`를 `HTTPServer s(..., 0); ASSERT_TRUE(s.start()); port = s.boundPort();`로 바꾼다. SetUp `ASSERT`에 메시지(포트·`start` 결과)를 붙인다 |
| 새 시험(`HttpServerLifecycleTest`) | ① 포트 0으로 시작하면 `boundPort()`가 1 이상이고 그 포트로 E1이 200 ② `stop()` 뒤 `boundPort()`는 0 ③ 포트 -1·65536은 지금처럼 `start()` false |

## 3. 시험·완료 기준
- 개발 빌드 `ctest` 전체, TSan 빌드(`-j3`) 전체, TSan 경고 0.
- 반복: `ctest --test-dir build-dev -R 'Http|EnergyPath|LockRules' -j8 --repeat until-fail:30`, TSan은 같은 범위 `--repeat until-fail:10`. 출력은 파일로 남기고 백그라운드 완료 알림으로 기다린다.
- J3 시험은 sanitize를 일부러 빼면 실패하는지 한 번 확인한다(확인 뒤 되돌림, 커밋 안 함).
- 운영 영향 없음: 운영 폴더·tmux `hac`·운영 DB를 건드리지 않는다. 모두 개발 폴더에서 한다.

## 4. 결정이 필요한 것

| # | 결정 | 안 | 추천 | 이유 |
|---|---|---|---|---|
| D1 | 포트 경쟁을 없애는 방법 | A `HTTPServer`가 포트 0 + `boundPort()`를 지원(운영 코드 약 10줄, main 동작 같음) / B 시험 도우미만: `start()`가 false면 새 포트로 최대 5번 다시 시도(시험 코드만) / C `ctest` `RESOURCE_LOCK`으로 HTTP 시험을 직렬 실행(CMake만) | **A** | 경쟁의 원인인 "닫고 다시 바인딩"을 없앤다. 14번 D6에서 승인된 방식이고 `TcpServer`와 규약이 같아진다. B는 원인을 남긴 채 증상만 흡수하고, C는 시험 시간이 늘어난다. **단, A는 "시험 코드만"이라는 요청 범위를 벗어난다**(운영 코드를 건드리지만 운영 동작은 바뀌지 않음). 범위를 엄격히 지키려면 B |
| D2 | 바꿀 범위 | A 서버를 시작하는 곳 전부(15곳 중 시작하는 곳) / B 간헐이 났던 `HttpServerTest` 픽스처만 | **A** | 같은 경쟁이 8파일 모두에 있다. 한 곳만 고치면 다음 간헐이 다른 파일에서 난다 |
| D3 | J3 시험에서 예외를 내는 방법 | A 가짜에 `thrownMessage` 칸 추가 / B 시험 전용 가짜 드라이버를 새로 만듦 | **A** | 기존 `throwOnSendCommand` 경로(`LockRulesTest`가 이미 500을 확인)를 그대로 쓴다. 기본값이 같아 다른 시험에 영향이 없다 |

결정은 3개다. 원인이 포트 경쟁이라는 것은 아직 추정이다. 14a 뒤 반복 실행(3절)에서 다시 나지 않으면 해소로 보고, 다시 나면 실패 메시지(포트·원인)를 보고 다시 판단한다.
