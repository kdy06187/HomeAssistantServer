| TCP 활성 재등록(D5 A) | `pickNewDevice`는 활성 ID를 계속 제외. 단 20초 동안 후보가 없고 **시작 뒤 새로 붙은 활성 ID가 있으면** `AlreadyRegistered`(공장 초기화한 등록 스위치), 없으면 `CommissionTimeout` |
| 테스트 | 활성 → AlreadyRegistered·DB·메모리·Matter 매핑 불변·새 노드 unpair 1회 / 숨김 → restored true·이력 유지 / 같은 ID 삭제(느린 unpair)와 등록 동시 → 삭제가 끝난 뒤 등록, 새 매핑 살아 있음(TSan 반복) / DB 저장 실패 → finalize(false)·새 노드만 정리 / TCP 후보 없음 + 활성 재접속 → AlreadyRegistered 판정 함수(순수 함수 시험) / 기존 E9·R7 시험 갱신 |
| 위험 | **상**. Matter 매핑 기록 시점이 바뀜(시리얼 읽기 → 등록 확정 뒤). 등록 확정 전 같은 노드 제어가 들어오면 "매핑 없음"으로 실행 안 함(지금 페어링 중 `isPairing`과 같은 결과) |

## 4. 남은 위험·확인
- **13b-2 Matter 매핑 시점 변경**(상): 시리얼 읽기 뒤 ~ 등록 확정 전 짧은 동안 새 노드 제어는 "매핑 없음". 기존 R7(DB 실패 정리)·E9 시험을 새 순서로 다시 씀.
- 종료: 13a 뒤 TCP 등록 중 SIGTERM 약 2~3초, Matter 페어링 중 약 1초(`cancelAll` → SIGTERM → 1초 SIGKILL). 시리얼 읽기 중이면 최대 1초 더.
- SimpleBLE 스캔 1초×5, BLE 예외, 실제 chip-tool 페어링 시간은 자동 시험 밖 → 6절 실기.
- 작업 표는 메모리만: 서버 재시작 뒤 E8 404 → 앱은 E1로 확인(계약 그대로).
- T-2: `local_addr`은 앱이 접속한 주소라 앱이 VPN·다른 서브넷으로 붙으면 기기가 닿지 못하는 IP일 수 있음(지금은 LAN 전용, 실패는 20초 시간 초과로 드러남).
- 간헐 관찰(12b): 병렬 ctest 포트 충돌 의심 1건 — 13b E8 시험이 늘면 재발 가능, 다시 나오면 픽스처 포트 방식 변경(후속 후보).
- TSan 빌드 `-j3` 이하.
