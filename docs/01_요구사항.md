작성: 2026-11-16 (1단계 기획). 입력: docs/01_기획-질문.md의 사용자 답변 Q1~Q8, analysis/문제점.md(기준 main 4875445).
상태: **승인됨(2026-11-16)**. Q-07은 "겹치는 것만 흡수"로 결정. 나머지 확인 필요(Q-01~Q-06)는 2단계 설계에서 결정. "확인 필요"는 답변으로 정해지지 않아 추측하지 않은 항목이다.

## 1. 개요

- **목적**: DIY 기기(TCP)와 Matter 기기를 REST로 제어하는 C++17 서버의 서버 중단·데이터 오염 결함을 없애고, 핵심 계층(DeviceManager, 드라이버 인터페이스)을 동시성에 안전하고 테스트 가능한 구조로 다시 설계한다.
- **대상 사용자**: 본인 1명. 안드로이드 앱(REST, 별도 저장소)과 기기 펌웨어(TCP JSON)가 서버의 클라이언트다.
- **운영 환경**: 지금은 본인 집 LAN, 리눅스 PC 1대. 나중에 본인이 외부에서 접속할 계획(외부 접속 대비 설계 필요).
- **성공 기준**: 6절의 1차 릴리스(Must) 항목이 모두 완료 기준을 통과한다. 즉 (1) P1 결함 재현 테스트가 수정 전 실패, 수정 후 통과, (2) TCP JSON 프로토콜 무변경, (3) 실기 시험 절차서를 사용자가 실행해 통과.

## 3. 기능 요구사항

우선순위(MoSCoW): **Must** = 1차 릴리스 필수, **Should** = 2차 릴리스(꼭 하지만 1차 뒤), **Could** = 여유 있으면.
테스트 종류: **[단위]** 순수 로직 테스트, **[통합]** 가짜(Fake) 드라이버 통합 테스트, **[실기]** 사용자가 직접 실행하는 절차서.
