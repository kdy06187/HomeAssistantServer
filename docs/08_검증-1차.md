## 7. 9c — chip-tool 저장소 영구 폴더 (사용자 승인 2026-11-20)

- 지원 확인(읽기만, 실제 기기 실행 없음, `/tmp` 파일 시각 불변 확인): 이 SDK(`f97b02f`) chip-tool은 서버가 쓰는 8가지 명령 — `onoff on/off`, `onoff read on-off`, `electricalpowermeasurement read active-power`, `electricalenergymeasurement read cumulative-energy-imported`, `basicinformation read serial-number`, `pairing unpair`, `pairing ble-wifi` — 의 도움말에 모두 `[--storage-directory]`가 있다("Defaults to $TMPDIR, with fallback to /tmp").
- 옮겨지는 것(SDK 소스 확인): commissioner 저장소 `chip_tool_config*.ini`(fabric 키·노드 정보), 플랫폼 KVS `chip_tool_kvs`(`Commands.cpp`가 `<dir>/chip_tool_kvs`), interactive history `chip_tool_history`.
- 안 옮겨지는 것: `chip_config.ini`·`chip_counters.ini`·`chip_factory.ini` — `CHIPLinuxStorage.h`가 컴파일 때 `/tmp`로 고정(`SYSCONFDIR` 등). chip-tool(컨트롤러)의 페어링 정보는 commissioner 저장소에 있으므로, 이 셋이 재부팅으로 사라져도 다시 만들어지고 페어링은 유지될 것으로 판단. **확인 필요** → 배포 뒤 첫 재부팅 때 제어 1회(06 4절).
- 위치: `../config/chip-tool` — 기존 규칙(실행 위치 기준 `../config/…`)과 같고, `config/`는 비밀 파일(토큰) 자리라 0700 대상이다. `db/`는 서버 DB 전용이라 피함. `.gitignore`에 추가.
- 코드: `MatterController` 생성자 5번째 인자 `storageDirectory`(기본 `../config/chip-tool`), `runChipTool`이 모든 인자 끝에 `--storage-directory <dir>`, `Initialize`가 `mkdir 0700`(있으면 `chmod 0700`, 파일이면 실패 → main은 기존대로 "초기화 실패" 로그).
- 테스트: `EveryChipToolCallUsesStorageDirectory`(8종 호출 전부), `InitializeCreatesPrivateStorageDirectory`(생성·권한 교정), `InitializeFailsWhenStoragePathIsAFile`, 기존 인자 비교 3개에 옵션 추가. **dev 245/245, tsan 245/245(경고 0)**.
- 영향: 새 저장소는 비어 있으므로 지금 `/tmp`에 페어링된 기기는 새 서버에서 보이지 않는다 → 결정 26(새로 설치·재등록)과 같은 결과라 추가 작업 없음.
