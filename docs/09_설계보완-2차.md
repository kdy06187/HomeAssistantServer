**추천 근거 한 줄씩**
- a: 위험 대상(같은 PC의 다른 계정)이 지금 없다(D-7). stdin은 이를 줄이려고 디스크 잔류·출력 노출·실패 판정 약화라는 새 위험 3개를 들여온다. 인자 방식은 공백·따옴표 문제도 없다(execv).
- b: "반쯤 켜짐"은 9b에서 이미 해소. 남은 구멍은 `SO_REUSEPORT`로 두 인스턴스가 8000을 함께 여는 것.
- c: 측정 1회(약 3초)뿐이라 근거가 약함. 13번이 비동기라 늘려도 앱이 기다리지 않음.
- d: `DriverType`은 플러그에 붙어 있어 어느 TCP 연결이 PC인지 알려 주지 않는다. 핸드셰이크는 펌웨어·DB·앱 변경 없이 판별 가능한 유일한 근거.

## 2. 항목끼리 얽힌 점 (설계 결정 시 함께 볼 것)
1. **d ↔ 12번**: 현재 TCP 커미셔닝의 `closeConnectionsNotIn(활성 ID)`가 미등록 연결 = **PC 에이전트 연결도 닫는다**. 12번 "미식별 30초"·"커미셔닝 신규 후보(새 MAC·활성 아님)"도 PC 에이전트를 잘못 잡을 수 있다 → d의 연결 종류로 셋 다 제외. 그래서 T5를 12번(accept 변경)과 묶는 것을 추천.
2. **a ↔ 현재 동작 문서**: 서버는 이미 `--storage-directory ../config/chip-tool`을 넘긴다. stdin(B)을 고르면 history는 `/tmp`가 아니라 `../config/chip-tool/chip_tool_history`(0600)에 생긴다(chip-tool 소스 확인). 08 SEC-02의 "history는 실기 때 생긴 파일"은 그대로 맞다.
3. **a ↔ 성공 판정**: interactive 루프는 끝에서 종료 상태를 성공으로 둔다(소스) → B를 고르면 "종료 코드 0 + 성공 문구" 중 종료 코드가 의미를 잃을 수 있다(실기 확인 전 단정 안 함).
4. **c ↔ SEC-1차-06**: 대기를 늘리면 사칭 등록 창이 길어진다. 12번의 MAC 후보 제한 + d의 PC 에이전트 제외로 상쇄.

**총평**
- 집 LAN·1인 PC 전제에서 a·b는 추천안(인자 유지, `SO_REUSEPORT` 끄기)으로 충분하다. 단 SEC2-02(마스킹 목록에 SSID 없음, 마스킹·자르기 순서)는 13번 테스트에 넣는다.
- 가장 중요한 것은 d: INIT은 분류일 뿐 인증이 아니므로 위장(SEC2-08)이 "가짜 종료 확인 → 플러그 차단"(SEC2-09)으로 이어지지 않게 설계에서 막는다.
- 사용자가 정할 것: ① INIT에 공유 비밀을 넣을지(에이전트 수정) 아니면 "PcAgent 1개, 먼저 붙은 살아 있는 연결 우선" ② 에이전트 없음 정책 (가)/(나)와 PC ON 경고 수준 ③ 핸드셰이크를 연결별 스레드로(권고) ④ SSID 마스킹 여부.
- 남은 확인: 계약 E3의 평문 전송 범위(SEC2-04)는 문서 대조만 필요.
