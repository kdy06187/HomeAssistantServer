## 2. 항목끼리 얽힌 점
1. **d ↔ 12b ↔ 커미셔닝**: 지금 `closeConnectionsNotIn(활성 ID)`(`TCPDriver.cpp:102`)가 미등록 연결 = PC 에이전트도 닫는다 → R-4로 제외. 에이전트 ID를 설정으로 미리 알기 때문에 별도 분류 상태가 필요 없다.
2. **d ↔ PCDriver(코드 확인)**: `PCDriver`는 전달 결과를 보지 않고 무조건 `{true,45}`(`PCDriver.cpp:20~30`). 따라서 d의 효과는 "에이전트만 받음 + 스위치 1초 지연 제거"이고, 에이전트가 못 받은 경우의 차단은 정책 (가)대로 남는다(R-7 경고).
3. **c ↔ 11·13**: 11번(SIGTERM)은 12b·13보다 먼저 들어간다. 11~13 사이 TCP 등록 중 종료는 5초를 넘을 수 있다(지금도 15초). 13번 취소 플래그로 해소.
4. **c ↔ SEC-1차-06**: 대기를 늘리면 사칭 등록 창이 길어진다. 12b의 "새 MAC·활성 아님·PC 에이전트 아님" 후보 제한으로 상쇄.
5. **a ↔ 러너 출력 상한(코드 확인)**: 러너는 1MiB에서 **자른 뒤** 마스킹한다(`ProcessChipToolRunner.cpp:256~295`) → M-4로 순서 고정.

## 6. 다루지 않은 것
- Gemini 1차 검증의 V1·V5·V8·V11·V12①② 원문은 총괄 PC에만 있어 이 저장소에서 확인하지 못했다. 번호 배정(V1→10, V5·V8·V12②→11, V11·V12①→13)만 진행현황 기준으로 유지. 이번 교차 리뷰 지적은 총괄 판정 요약으로 반영했다(원문 미열람).
- SEC-1차-01·05·08·09·11(10번)과 SEC-1차-07·12의 나머지는 기존 설계(3.7·3.8) 그대로.
- `02_설계.md` 본문 중 4절 마이그레이션 3·4단계, 3.2 `renameDeviceId`, 9절 S-06 줄은 인용 줄로만 "삭제 예정"을 표시했다. 최종 승인 때 본문에서 지운다.
