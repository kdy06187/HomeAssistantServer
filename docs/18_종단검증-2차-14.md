## 1. 서버 쪽 확인 — curl (블록 B, 약 25분, 기기 초기화 없음)

| # | 확인 | 명령 | 기대 |
|---|---|---|---|
| B-1 | E1 목록, 1차 DB 그대로 읽힘 | `curl -s -H @$AUTH $B/api/devices; echo` | 200 `{"totalCount":2,"devices":[…]}`, 키 `deviceId`·`protocolType`·`state`·`ip`. 플러그 `ip:null`, `ARD_…`의 `ip`는 1차가 저장한 값 또는 `null`(어느 쪽인지 기록) |
| B-2 | 틀린 토큰 POST → 401 + JSON (N-03) | `curl -s -i -X POST -H 'Authorization: Bearer wrong-token-on-purpose' -H "$J" -d '{"deviceId":"x","command":"ON"}' $B/api/control; echo` | `401`, `WWW-Authenticate: Bearer`, `{"error":{"code":"UNAUTHORIZED","message":"인증에 실패했습니다."}}`(연결이 먼저 끊기지 않음) |
| B-3 | 토큰 없음 GET | `code $B/api/devices` | `401` |
| B-4 | 413 (16KiB 초과) | `head -c 17000 /dev/zero \| tr '\0' a \| curl -s -i -X POST -H @$AUTH -H "$J" --data-binary @- $B/api/control; echo` | `413` + `{"error":{"code":"PAYLOAD_TOO_LARGE","message":"요청 본문이 너무 큽니다."}}`. **연결이 먼저 끊겨 본문 없이 끝나도 계약상 정상**(`curl: (56)`·`(52)`) — 어느 쪽인지 기록 |
| B-5 | E5 상태 / 없는 기기 404 / 형식 틀린 ID 404 | `curl -s -H @$AUTH "$B/api/devices/$PLUG/state?isManualRefresh=true"; echo; code -H @$AUTH $B/api/devices/NOPE_1/state; code -H @$AUTH "$B/api/devices/a.b/state"` | 200 `{"deviceId":…,"state":"ON"\|"OFF"}` / `404`(`DEVICE_NOT_FOUND`) / `404`(`NOT_FOUND`) |
| B-6 | E6 전력 / TCP 기기 400 | `curl -s -H @$AUTH $B/api/devices/$PLUG/energy; echo; curl -s -H @$AUTH $B/api/devices/$OLD_SW/energy; echo` | 200 `{"deviceId","state","activePower_mW":<정수>,"totalEnergy_mWh":<정수>}` / `ARD_…`는 `.`이 있어 **404 `NOT_FOUND`**(계약 §1 `{deviceId}` 형식, 실행 때 정정). 400 `UNSUPPORTED_OPERATION`은 D-2 뒤 `TCP_<12자>`로 확인 |
| B-7 | E7 원본 모드 | `curl -s -H @$AUTH "$B/api/devices/$PLUG/energy/history?limit=3"; echo` | 200 `logs` 3건 이하, 오래된 것부터, `timestamp`가 `…Z`, `truncated` |
| B-8 | E7 일/주/월 집계 | `for p in day week month; do curl -s -H @$AUTH "$B/api/devices/$PLUG/energy/history?from=$(date -d '-13 day' +%F)&to=$(date +%F)&period=$p"; echo; done` | 200, `period`·`utcOffset:"+09:00"`·`buckets`. day는 14개, week는 월요일 시작(첫·끝 주는 `from`·`to`로 잘림), month는 1~2개. 기록 없는 구간 `sampleCount:0`. 대조: `sqlite3 -readonly $T/db/home_assistant.db "SELECT count(*), min(timestamp), max(timestamp) FROM state_history_logs WHERE device_id='$PLUG';"`로 기록 수·기간을 보고, 같은 범위의 `sampleCount` 합과 비교(시각은 DB 저장 형식 그대로, +09:00 날짜 경계 차이는 기록) |
| B-9 | E7 400 조건 | `for q in 'from=2026-02-30&to=2026-03-01' 'period=year' 'limit=0' 'period=day&from=2026-11-01' 'from=1999-12-31&to=2000-01-01'; do code -H @$AUTH "$B/api/devices/$PLUG/energy/history?$q"; done` | 모두 `400` |
| B-10 | E2 502 (옛 `ARD_` 기기는 연결이 없음) | `curl -s -i -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$OLD_SW\",\"command\":\"ON\"}" $B/api/control; echo` | `502` `DEVICE_UNREACHABLE`(서버 `OFFLINE` 기록) |
| B-11 | E2 200 / **202 `pendingCommand`** / 같은 명령 재전송 / ON으로 취소 | 아래 C-3 확인 뒤 실행 | 아래 |
| B-12 | E2 400 | `code -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$PLUG\",\"command\":\"TOGGLE\"}" $B/api/control` | `400` |

**B-11 E2 지연 OFF (PC가 실제로 꺼지지 않게)** — 먼저 3절 C-3의 세 가지를 확인한다(전등·원본 에이전트 꺼짐·가짜 MAC).
```bash
for c in ON OFF OFF; do curl -s -i -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$PLUG\",\"command\":\"$c\"}" $B/api/control | sed -n '1p;$p'; sleep 3; done
```
기대: ON `200` `{"deviceId",…,"state":"ON"}` → OFF **`202`** `{"deviceId",…,"state":"ON","pendingCommand":"OFF","delaySeconds":45}` → 같은 OFF `202`(`delaySeconds`가 약 42로 줄어듦, 종료 메시지 재전송 없음). 로그 `[TCPDriver] PC 에이전트(TCP_020000000001) 연결 없음 — 종료 메시지 못 보냄, 45초 뒤 전원 차단`. **45초 뒤 전등 꺼짐**, PC는 켜진 채. 이어서 취소 확인:
```bash
curl -s -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$PLUG\",\"command\":\"ON\"}" $B/api/control; echo; sleep 3; curl -s -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$PLUG\",\"command\":\"OFF\"}" $B/api/control; echo; sleep 5; curl -s -X POST -H @$AUTH -H "$J" -d "{\"deviceId\":\"$PLUG\",\"command\":\"ON\"}" $B/api/control; echo
```
기대: 마지막 ON이 대기 중 OFF를 취소(`[Scheduler] 지연 OFF 취소: ACA7F18822A5, …` 로그), 60초 동안 전등 켜짐 유지.

## 3. 기기 경로 확인 (블록 D, 약 45분, **스위치 초기화 2회, 플러그 0회**)

초기화를 줄이려고 순서를 이렇게 짠다:
- 플러그는 **운영 fabric 복사본으로 그대로 제어만** 한다. 삭제·재페어링을 하지 않으므로 플러그 초기화가 필요 없다(13번에서 플러그는 unpair 뒤 BLE로 다시 안 나와 매번 공장 초기화가 필요했다).
- 등록·삭제·복구·이미 등록 경로는 모두 TCP 스위치로 확인한다. E4 `unpaired:true`(RESET)가 스위치를 BLE 모드로 돌려보내므로, 그다음 등록에는 초기화가 필요 없다.

### C-3 PC 보호 (B-11 전에 반드시)
1. 플러그에 **전등**(P-5).
2. 메인 PC에서 원본 `pc_client.pyw`가 **안 도는지** 확인하고, 돌면 끈다(작업 관리자에서 `pythonw` 확인).
3. 시험 서버의 `HAC_PC_AGENT_MAC=02:00:00:00:00:01`(0.6 시작 로그 `TCP_020000000001`).

셋 중 하나만 지켜져도 PC는 꺼지지 않는다. 세 겹으로 둔다.

### D-1 옛 `ARD_` 기기 삭제 → `unpaired:false` (전환일 T-7 예행, 앱으로)
1. 앱에서 `ARD_192.168.219.105` 스위치를 삭제한다(앱 삭제 항목).
2. 기대: 앱 경고 "기기 쪽 해제 실패, 기기 초기화 필요"(`unpaired:false` — 그 ID로 연결된 기기가 없어 RESET을 못 보냄). 서버 로그 `[DeviceManager] 기기 삭제(숨김) 완료 : ARD_192.168.219.105 (기기 쪽 해제 실패)`. 대조:
   ```bash
   curl -s -H @$AUTH $B/api/devices; echo; code -H @$AUTH $B/api/devices/$OLD_SW/state; sqlite3 -readonly $T/db/home_assistant.db "SELECT device_id, deleted_at FROM devices;"
   ```
   기대: E1에 `ARD_` 없음, E5 `404`, DB `deleted_at` 채워짐(숨김, 행은 남음).

### D-2 🔒 스위치 초기화 ① → 앱으로 TCP 등록 (E3 202 → E8, 409)
1. 🔒 스위치 초기화(P-4) → BLE 등록 모드.
2. 앱에서 TCP 기기 추가(SSID·비밀번호 입력, 서버 주소는 앱 기본 = 빈 `payload`).
3. 등록이 진행되는 동안(로그 `BLE 스캔 시작...` 뒤) 원래 터미널에서 두 번째 E3:
   ```bash
   printf '{"protocolType":"TCP_DIY","deviceName":"x","payload":""}' | curl -s -i -X POST -H @$AUTH -H "$J" -d @- $B/api/commission | sed -n '1p;$p'
   ```
   기대: `409` `COMMISSION_BUSY`.
4. 기대: 앱 등록 성공. 로그 `TCP 등록 서버 주소 = 접속 주소 <SERVER_IP>` → `기기 발견!` → `커미셔닝 완료 : … (TCP_<12자>, N초)`. E1에 `TCP_<12자>`, `ip`, E8 `restored:false`. → `SW=<그 ID>`.
5. 시간 기록: 접수→완료 초(13번 K-12 약 10초).

### D-3 삭제 → 재등록 `restored:true` (초기화 없음)
1. 앱에서 `$SW` 삭제 → 기대 `unpaired:true`(경고 없음), 로그 `[TCPDriver] 아두이노 연결 해제 완료: <SW>`, `기기 삭제(숨김) 완료 : <SW>`(뒤에 해제 실패 표시 없음), 스위치 BLE 모드로.
2. 앱에서 다시 TCP 등록(같은 SSID·비밀번호).
3. 기대: 성공, 같은 `$SW`, 앱 복구 알림(`restored:true`). 대조 `sqlite3 -readonly $T/db/home_assistant.db "SELECT device_id, deleted_at FROM devices WHERE device_id='$SW';"` → `deleted_at` 빈칸.
4. 스위치가 BLE로 안 나오면 🔒 초기화(+1회, 3절 기록에 적음).

### D-4 🔒 스위치 초기화 ② (활성인 채) → `ALREADY_REGISTERED`
1. 🔒 활성 등록된 스위치를 초기화 → 앱에서 TCP 등록.
2. 기대: 앱 "이미 등록된 기기" 표시, E8 `FAILED` + `"code":"ALREADY_REGISTERED"`, 로그 `새 기기 없음, 이미 등록된 기기가 다시 접속함 : <SW>`(13번 K-14 ①). 스위치는 활성 그대로 동작(앱에서 켜기/끄기 1회).

### D-5 (선택, Q2) Matter 앱 등록 경로
앱 팀 체크표에 Matter QR 등록이 꼭 들어가면 이 항목을 한다. **플러그 초기화 +2회**(시험 등록 1 + 운영 재등록 1)다. 앱에서 플러그 삭제(`unpaired:true`) → 🔒 공장 초기화 → 앱 Matter 등록 → `restored:true`. 끝나면 6절 5의 플러그 재등록 절차를 따른다.

| 메모 | 내용 |
|---|---|
| 비밀값 grep | 블록 D 뒤 `read -rs -p 'Wi-Fi 비밀번호: ' PW; echo; grep -cF -- "$PW" $T/server-*.log; grep -cFf $T/config/api_token $T/server-*.log; unset PW` → 모두 `0` |
| 등록 중 종료·K-4·R-1 | 13번에서 확인했으므로 이번에는 하지 않는다 |
