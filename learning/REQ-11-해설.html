REQ-11 해설 — 시험 포트 경쟁 없애기 · 로그 주입 회귀 시험 (2차 14a)

간헐 실패 2건의 의심 원인(빈 포트를 고른 뒤 다시 여는 틈)을 없애고, 처리 못 한 예외 로그가 한 줄로만 남는지 지키는 시험을 더했다. 운영 동작은 그대로다(main은 8000을 넘김).

1. 무엇이 문제였나 — "골라 두고 닫았다가 다시 열기"

고친 뒤: 서버가 직접 bind(0)으로 열고(httplib bind_to_any_port), 받은 포트를 boundPort()로 알려 준다. 닫았다 다시 여는 단계가 없으니 틈이 없다. TcpServer가 이미 쓰던 규약과 같다.

2. 바뀐 코드

// src/HTTPServer.cpp start()
if (!state->server.bind_to_port(mBindAddress, mPort)) {
const int boundPort = mPort == 0 ? state->server.bind_to_any_port(mBindAddress)
                                 : (state->server.bind_to_port(mBindAddress, mPort) ? mPort : -1);
if (boundPort <= 0) {
...
mBoundPort = boundPort;   // stop()에서 0으로
// 시험 픽스처
port = findFreePort();
server = std::make_unique<HTTPServer>(..., port);
server = std::make_unique<HTTPServer>(..., 0);
ASSERT_TRUE(server->start());
port = server->boundPort();
운영은 그대로main은 8000을 넘긴다. 시험 GivenPortIsUsedExactlyAsBefore가 "지정 포트로 열리고 로그에도 그 포트"를 확인한다.
포트 0은 이제 정상 값예전 시험은 0을 범위 오류로 봤다 → 범위 시험에서 0을 뺐다(-1·65536은 여전히 실패).
같은 포트 재사용 시험처음 연 서버의 boundPort()를 다음 서버에 넘긴다(Limits 시험).

3. J3 — 로그 주입 회귀 시험

예외 문구에 \r\n[HTTPServer] fake line을 넣고 E2를 보낸다. sanitize가 빠지면 로그에 가짜 줄이 하나 더 생긴다.

4. 응용 실습

Q1. findFreePort()를 그대로 두고 "start 실패면 5번 다시 시도"로 고치면 무엇이 남나?

실패는 숨지만 틈은 그대로다. 다른 프로세스가 그 포트를 잠깐 잡았다 놓는 경우처럼 원인을 확인할 기회도 사라진다. 원인을 없애는 쪽(포트 0)이 낫다.
