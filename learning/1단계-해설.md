# 1단계 해설: 요구사항 문서(SRS) 읽는 법

대상: `docs/01_요구사항.md`. SRS(Software Requirements Specification)는 "무엇을 만들지"를 적은 문서다. "어떻게"는 2단계 설계서에서 다룬다.

## 1. 문서 구성과 나눈 이유

| 부분 | 역할 | 나눈 이유 |
|---|---|---|
| 기능 요구사항(3절, REQ) | 시스템이 **하는 일** | 기능 하나가 테스트 하나로 이어지게 하려고 |
| 비기능 요구사항(4절, NFR) | **얼마나 잘** 하는지(안전성, 응답성, 호환성) | 여러 기능에 공통으로 걸리는 품질이라 따로 둬야 빠지지 않는다 |
| 범위 밖(6절) | 이번에 **안 하는 것**과 이유 | 일이 슬금슬금 커지는 것(범위 팽창)을 막고, 안 한 이유를 남기려고 |
| 가정·미해결 질문(7절) | 확인하지 못한 채 **전제한 것** | 추측을 사실처럼 쓰지 않으려고. 틀리면 어느 요구사항이 흔들리는지 추적할 수 있다 |

이 문서에서 NFR-04("TCP JSON 프로토콜은 100% 유지")가 좋은 예다. 기능이 아니라 제약이지만 REQ-05의 설계 선택지를 크게 줄인다.

## 2. MoSCoW와 "검증 가능한 완료 기준"

- **MoSCoW**: Must(필수) / Should(해야 함, 다음 차례) / Could(여유 있으면) / Won't(이번엔 안 함). 모든 항목을 "중요"로 두면 우선순위가 없는 것과 같으니, 자원이 모자랄 때 무엇을 먼저 할지 정하는 도구다. 이 문서는 Must 10개, Should 8개, Could 0개이고, 근거도 같이 적었다(예: REQ-08은 서버 중단이 아니라 Should).
- **검증 가능한 완료 기준**: "됐는지"를 사람마다 다르게 판단하면 안 된다. 입력과 기대 결과가 숫자나 조건으로 적혀 있어야 테스트로 바꿀 수 있다.

**좋은 예: REQ-03(전력량 집계)**
완료 기준이 "정상(100) → 실패 → 정상(110) 순서에서 누적 증가분이 10"이다. 입력, 순서, 기대값이 모두 있어서 그대로 단위 테스트가 된다. 통과/실패에 이견이 없다.

**개선 여지 있는 예: REQ-01(락 안전)**
"제한 시간 안에 끝남"에서 시간이 숫자가 아니다. "재현 여부는 확인 필요"라서 수정 전에 실패한다는 보장도 없다. 수정 전 실패, 수정 후 통과가 안 되면 고쳐졌는지 알 수 없다. 개선안은 "N초 이내, M회 반복"처럼 수치를 정하고, 재현이 안 되면 ThreadSanitizer 경고 0을 주된 기준으로 삼는 것이다. 문서도 이 약점을 "확인 필요"로 솔직하게 표시했다.

비슷한 약점이 REQ-15(설계 산출물 기준만 있음)와 NFR-02(수치 초안 1초)에도 있다. 찾아보자.

## 3. 역추적 표(8절): 문제점 → REQ → 설계 → 테스트

```
문제점(analysis/문제점.md)  →  REQ  →  설계 요소(2단계)  →  코드(3단계)  →  테스트(완료 기준)
        B-02            →  REQ-03 →   통계 갱신 규칙   →     수정      →  [단위] 100→실패→110 = 10
```

- 왼쪽 끝은 0단계 분석의 문제점 ID, 오른쪽 끝은 완료 기준(테스트)이다. 사슬이 끊기는 곳이 문제다.
- **REQ가 없는 문제점**: 범위 밖으로 뺀 이유가 6절에 있는지(A-04, A-06 등), 아니면 미배정(N-08 등)인지 보여준다. "누락"과 "의도적 제외"를 구분할 수 있다.
- **문제점이 없는 REQ**: 필요 없는 일일 수 있다. (REQ-17, 18은 출처가 Q8 답변이다. 문제점이 아니라 사용자 요청에서 왔다는 뜻이다.)
- 2단계에서는 설계서의 각 요소에 REQ-ID를 붙이고, 3단계에서는 테스트 이름에 REQ-ID를 넣어 사슬을 잇는다. 요구사항이 바뀌면 표를 따라가서 고칠 곳을 찾는다.

## 5. 이해도 확인 질문

1. 요구사항 "서버가 빨라야 한다"를 REQ-06 수준의 좋은 요구사항으로 고치려면 무엇을 추가해야 할까?
2. 역추적 표에서 N-08이 "(미배정)"인 채 2단계로 넘어가면 어떤 문제가 생길까?
3. REQ-14(TLS 가이드)는 코드 변경이 작은데도 Must이고, REQ-08은 오동작인데도 Should다. 이 기준은 무엇일까?

1. 측정 대상, 수치, 조건이 필요하다. 예: "기기 목록 요청이, 전력 조회 10초 중에도 1초 안에 응답한다"(NFR-02, REQ-06). 그리고 테스트 종류([단위]/[통합]/[실기])를 정한다.
