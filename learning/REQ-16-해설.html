REQ-16 · REQ-10 해설 (2차 13a)

chip-tool 출력의 비밀값 가리기 순서, 서버 종료 때 등록을 빨리 끝내는 취소 플래그, 그리고 작은 로그 정리 두 건 (3단계 2차 13a, 학습 강도: 균형).

1. 한눈에 보기

13a-1 마스킹가릴 값 = SSID(4바이트 이상)·비밀번호·코드·PIN, 빈 값 제외. 잘린 출력은 마스킹 전에 끝을 더 버린다. 실패 로그는 끝 4KiB.
13a-2 죽은 분기등록 파일에 nodeId가 있으면 "이미 등록"으로 성공하던 경로 삭제(새 번호는 늘 새로 발급).
13a-3 취소 플래그commission(…, cancelRequested). TCP는 스캔 1초마다·대기 1초마다, Matter는 페어링 전·후 확인. 종료 지연 약 26초 → 2~3초.
13a-4 로그접속 인사 줄(첫 요청 전 JSON 한 줄)은 경고 안 함. 에이전트가 방금 끊겼으면 1초 기다리지 않고 "연결 끊김 … 45초 뒤 전원 차단".

2. 흐름 그림 ①: 비밀값 가리기 순서 (M-4)

3. 흐름 그림 ②: 종료 신호가 등록을 끊는 길 (취소 플래그)

플래그는 값이 아니라 참조로 넘긴다(const std::atomic<bool>&). 드라이버가 오래 도는 동안 바깥에서 바뀐 값을 계속 읽어야 하기 때문이다. 13b에서는 DeviceManager의 플래그 대신 CommissioningService가 자기 플래그를 넘긴다 — 드라이버 코드는 그대로.

5. 용어 풀이

용어뜻
협력적 취소(cooperative cancellation)스레드를 강제로 죽이지 않고, 작업이 스스로 "그만하라는 표시"를 주기적으로 확인해 끝내는 방식. 확인 간격이 곧 최대 지연(여기서는 1초)
FIN / 반쯤 열린 연결상대가 정상 종료하면 FIN이 와서 poll의 POLLRDHUP로 바로 안다. 정전처럼 FIN이 없으면 응답 대기(1초)가 끝나야 안다
마스킹 순서 불변식"자르기 → 경계 정리 → 마스킹 → 로그 자르기". 앞 둘의 순서가 바뀌면 조각이 샌다

6. 이해도 질문

  1. 비밀값이 "abcd"(4바이트)뿐일 때, 잘린 출력의 끝에서 몇 바이트를 버리나? 왜 4가 아니라 3인가?
  2. SSID가 3바이트면 가리지 않는데, 비밀번호가 3바이트면 왜 "가리지 않음" 대신 "실패 출력을 아예 안 남김"을 택했나?
  3. 스캔을 5초 한 번에서 1초 다섯 번으로 바꾸면 종료 지연 외에 어떤 동작이 함께 달라지나? (힌트: 찾으면 멈춤)
  4. 플래그를 bool 값으로 넘기면 무엇이 깨지나?
답 보기
  1. 3바이트. 4바이트 전부 남아 있으면 마스킹이 찾아서 가린다. 못 가리는 것은 잘려서 일부(최대 3바이트)만 남은 조각뿐이다.
  2. SSID는 공개 방송되는 값이라 노출 피해가 작다. 비밀번호는 노출되면 안 되는데, 1~3바이트를 ***로 바꾸면 출력 곳곳이 망가져 진단이 안 된다 → 둘 다 피하려고 출력 자체를 생략.
  3. 예전엔 기기를 찾아도 5초를 다 기다렸다. 이제는 찾은 회차에서 멈춰 등록이 최대 4초 빨라진다(실기 K-12에서 발견율 확인).
  4. 호출 시점의 값이 복사되어, 등록 도중 종료가 시작돼도 드라이버는 끝까지 false만 본다.

7. 응용 실습 — 빈칸 채우기

아래 함수는 접속 대기 루프다. 빈칸을 채워 "1초마다 취소 확인 → 새 후보가 있으면 성공"이 되게 하라. 정답은 src/TCPDriver.cpp의 commission.

for (int waited = 0; waited < kCommissionConnectWaitSeconds; ++waited) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    if (/* ① */) return Result<CommissionOutcome>::failure(ErrorCode::/* ② */, "접속 대기 취소");
    const auto candidate = TcpCommissionCandidate::pickNewDevice(/* ③ 시작 전 스냅샷 */, server_.connectedIds(),
                                                                 activeDeviceIds, server_.pcAgentId());
    if (candidate) return /* ④ */;
}
정답

① cancelRequested ② Cancelled ③ existing_ids(= closeConnectionsNotIn의 반환값) ④ Result<CommissionOutcome>::success(CommissionOutcome{*candidate, server_.peerIpOf(*candidate).value_or("")})

응용 과제: trimTruncatedTail를 바꾸지 않고, 비밀값이 출력 중간에서 1MiB 경계에 걸친 경우를 만드는 시험을 직접 써 보라(tests/unit/ProcessChipToolRunnerTest.cpp의 SecretCutByOutputCapLeavesNoFragment를 참고하되 비밀값 두 개, 길이 다르게).
